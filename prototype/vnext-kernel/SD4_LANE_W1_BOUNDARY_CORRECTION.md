## 1. The expiry inequality — refutation attempted, none lands

All four premises verified firsthand; the refutation was attempted against #179
and every other authoritative vNext clock.

| Artifact | Clock | Rule | Semantics |
| --- | --- | --- | --- |
| kernel `:665` | signed-action `deadline` | `now > deadline → Expired` | inclusive deadline |
| kernel `:691` | containment `containedUntil` | `now >= containedUntil → NORMAL` | **exclusive expiry** |
| kernel `:1228` | recovery `expiresAt` | `now > expiresAt → Expired` | **inclusive — the outlier** |
| model `:1140` | migration `deadline` | `clock > deadline → expired` | inclusive deadline |
| model `:696, :1031, :1040, :1358` | every expiry | `clock >= expiry → expired` | **exclusive expiry, uniformly** |
| #179 `:755` | containment `expiresAt` | *"set once … no principal may move it"* | **silent on the inequality** |

**The kernel already distinguishes an inclusive *deadline* from an exclusive
*expiry*** — for containment — and breaks its own convention for recovery
alone. The model holds the distinction uniformly. #179 states no inequality
for any clock; its only clock inequalities are duration orderings
(`bindDelay >= recoveryDelay`). **No refutation exists in authority**, and the
prototype cannot decide the question because it is the artifact under review.

## 2. Boundary probes — asserting the mined instant, not a named one

Every probe asserts the block timestamp the transaction **actually executed
at**. `setNextBlockTimestamp` is used where a transaction must land on a
one-second boundary; a view is only read from a block already mined at the
probe instant.

- **E−1 (`expiresAt − 1`):** a quorum cancellation executed at exactly
  `expiresAt − 1` **succeeds** — its success *is* the liveness assertion, since
  it requires `effectiveLive` in its own block. Budget unchanged. A fresh
  correct request initiates with a full 7 d delay and 21 d expiry measured from
  its own mined instant, executes, and the credential spends.
- **E0 (`expiresAt`):** block mined at exactly `expiresAt`; `effectiveLive`
  reads false; the stale `active` byte is still set and carries nothing.
  `executeRecovery` → `Expired`; credential challenge → `NoRecovery`; quorum
  cancellation → `NoRecovery`; **a refused challenge consumes nothing**.
  `bindMigration` succeeds with no sweeper. Fresh initiation succeeds and the
  live-request guard (`BadState`) **does not fire — it is not overwrite**.
  Completed through a spend.
- **E+1:** identical results one second later.

## 3. The challenge epoch — adopted

```text
I-RECOVERY-CHALLENGE-EPOCH

The spending credential's bounded recovery-challenge budget is independent of
RecoveryRequest identity, RecoveryRequest lifetime, credentialGeneration,
ordinary credential rotation, and credential material equality.

It persists across credential challenge, guardian-quorum cancellation, request
expiry, fresh initiation, and ordinary credential rotation.

It resets ONLY when guardian recovery successfully executes.

Authority status: DERIVED_REQUIREMENT_ADOPTED_FOR_VNEXT
```

**#179 does not state the reset boundary.** The derivation:

- reset on ordinary rotation → the current credential manufactures fresh veto
  budget by rotating in place → **H-03** (measured, Lane V2: six cancels where
  two are permitted);
- never reset → every legitimately recovered future credential permanently
  loses the D1/H-15 bounded defence (measured, Lane W B2);
- **successful guardian recovery is the separating event** because the
  outgoing spending credential cannot authorise it, and the recovery trust root
  (§22 D1) is what installs the post-recovery authority.

**Identical-material recovery re-tested on the half-open kernel: the epoch
resets.** The bytes did not change; the authority was exercised. The reset
follows the authority transition, not byte equality.

## 6. K-9 and SD-9 — root-cause record

**`K9_GUARDIAN_CANCEL_CONFORMANCE = MISSING_IN_PROTOTYPE`** (Lane V2 §2, unchanged).

> **SD-9 — `RECOVERY_LIFECYCLE_STATE_OWNERSHIP`.** The kernel implements one
> recovery object with one stored liveness flag where the architecture and
> reference model specify two lifecycles (request; challenge epoch), three
> enumerated exits, and wall-clock liveness.
>
> - **a.** bounded challenge state incorrectly shares `RecoveryRequest`
>   lifetime — any correct expiry cleanup refunds it (measured);
> - **b.** an expired `RecoveryRequest` retains blocking effect on
>   `bindMigration` and needs a principal to clear (`I-RECOVERY-TERMINATION`);
> - **c.** K-9 guardian cancellation is absent (`:832`, `KERNEL_ADMISSION.md:37`);
> - **d.** direct overwrite substitutes for explicit lifecycle termination;
> - **e.** recovery expiry uses the wrong equality boundary — `>` at `:1228`
>   against the kernel's own `>=` convention at `:691` and the model's uniform
>   `>=`.

**On (e)'s causal root, stated rather than glossed:** a–d share *state
ownership* as their cause; (e) is a boundary-convention slip. They are grouped
because they share the *deeper* root — the kernel has no single lifecycle
specification to conform to, so each axis (ownership, exits, boundary) drifted
independently. **SD-10 stays separate**: its root is generation binding
(`I-APPROVED-REQUEST-PRESERVATION`), not lifecycle ownership.

## 7. `recovery()` getter compatibility — Option B frozen

`RecoveryRequest public recovery` autogenerates an 8-field tuple getter. Two
tooling consumers index it **positionally**: `stateful/invariants.ts:191-198`
(`recoveryRaw[6]` is `challengesUsed`) and `stateful/actions.ts:876-878`.

| | A — breaking getter | **B — compatibility view** | C — mirror storage field |
| --- | --- | --- | --- |
| selector | unchanged (`recovery()`) | **unchanged** | unchanged |
| ABI tuple | **8 → 7 fields — breaks** | **identical 8 fields** | identical |
| storage | struct repacks (−4 bytes) | struct repacks (−4 bytes); `recovery` becomes `internal` | struct unchanged, +1 write per mutation |
| runtime bytes | slightly smaller | **+~60–120** for the explicit view | larger: every writer mirrors |
| semantic ambiguity | none | **one, documented**: field 6 reports the vault-scoped epoch inside a request-shaped tuple — right value, scope implied by position | **two sources of truth** |
| observable compat | **breaks** `invariants.ts:197`, `R` map; `actions.ts` survives (reads [0..2]) | **preserved, zero tooling churn** | preserved |
| tooling assumes autogen shape? | **yes** | yes — satisfied | yes |

**C is rejected adversarially:** a mirror field is a second authority; any
future writer that updates one location and not the other diverges silently —
exactly the class of defect SD-9a is. The "dead, never-written field"
sub-variant avoids dual authority but reports a frozen `0` forever through the
getter, which is worse than B.

**B preserves the interface truthfully with one source of truth.** Its cost is a
small view and one documentation obligation. **Frozen: B.**
